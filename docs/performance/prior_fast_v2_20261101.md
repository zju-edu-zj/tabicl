# 历史实验记录：已撤回的接收预取与短表 pilot（2026-11-01）

当前实现、纠正及新算法见 [流程重审与渐进过滤](prior_algorithmic_design_20261101.md)。本文件只记录撤回依据，不再提供已删除实验代码的启用命令。原有 DataLoader/node_pool 生成预取保留；额外 RankPrefetch、pilot→tail、histogram gate、其校准器及训练参数已移除。

## 保留的 CPU 工程优化

nearest-center 的 distance/argmin 融合避免创建完整距离矩阵，保留所有维度与 centers；满足成本门槛时复用重复输入。EM 保留完整软分配；graph 后代查询、bootstrap 索引、last-use 内存释放等优化保留。旧正式过滤的 full 路径保留，新 progressive 路径另行审计。

| 路径 | wall s | CPU s | tables/s | task p99 s |
|---|---:|---:|---:|---:|
| Torch distance A1 | 42.121 | 271.783 | 12.155 | 3.054 |
| native B1 | 36.411 | 231.339 | 14.062 | 1.981 |
| native B2 | 36.395 | 231.112 | 14.068 | 2.001 |

两边保留已有行压缩及 legacy 1-D。合并吞吐 +15.47%、CPU -14.78%，四轮过滤均调用 667 次、拒绝 155 次。这不是本轮新渐进过滤的收益，也不是 GPU 训练 step 收益。原始汇总见 [旧 CPU 结果](prior_fast_v2_cpu_20261101.json)。

## 为什么撤回额外接收预取

原 node_pool 已经异步生成。新增 rank 线程只接收 RPC、解码、ACK；不能增加生成容量。队列非空和 rank0 等待下降都不足以证明训练吞吐提高。

旧八卡短测：完整 prior、native distance、COMPILE_FRONTEND=all、前后向预热，node pool 56 workers/window128/2048 MiB、batch64/micro4/N2048，32 步、跳过前 8 步：

| dtype / 额外接收深度 | step 均值 ms | max-rank(prior+train) 均值 ms | 后者 p95 ms | 总 wall s |
|---|---:|---:|---:|---:|
| FP32 / 0 | 612.2 | 615.2 | 1306.6 | 316.7 |
| FP32 / 2 | 599.6 | 602.6 | 1345.2 | 99.7 |
| BF16 / 0 | 620.2 | 626.3 | 878.6 | 252.7 |
| BF16 / 2 | 618.9 | 623.6 | 1117.2 | 94.1 |

FP32 schedule=balanced，BF16=none。冷/热编译缓存不同，不能拿总 wall 算预取收益。BF16 rank0 prior 105.7→56.2 ms，但 max-rank prior 均值 288.6→300.8 ms。短测没有证明稳定净收益，因此删除新增线程，而不是继续叠队列。

逐 rank 三次预热在各进程并行执行，不等于串行 24 个优化步；但首次编译可能很久，旧首个 FP32 预热约 250.5 秒。它必须计入总训练时间，不能只报稳定 step。

原始汇总见 [旧 DDP 结果](prior_fast_v2_ddp_20261101.json)。它不包含新融合树/渐进过滤。

## 为什么撤回那一版 pilot，而不是否定早筛

旧实现先在 256 行上首次 fit 完整 graph，再生成 tail。其 histogram 分数包含交叉拟合分箱、有限的和/积探针；符合门槛才 accept/reject，否则 defer。

它的问题有三个：

1. graph 的统计量、centers、阈值等在短表上 fit，最终 N 行分布已经改变，即使所有动作都是 defer。
2. 边际分箱与有限低阶交互探针不能充分代表所有高阶交互、多跳及 converter 后的关系。
3. 10,000 候选拆成 63 个形状层，部分层样本过少；不能把零覆盖只归因于质量预算严格。

10,000 个候选中正式过滤拒绝 3,015 个，开发/验证分别 5,029/4,971。0.5% 和 5% 两种预算都没有产出可用门槛，冻结后新 seed 的 1,000 个候选也全部 defer。**这不是准确率 100%，更不是“所有提前筛选都无效”。**

完整表已经 fit 后截取前缀所得到的高 AUC，也不能替代真实 short-fit pilot 路径的验证。

## 短表拟合改变了什么

seed=44、各 1,000 个候选，全部执行正式过滤；full-fit 接受 683 个，pilot-fit 接受 688 个。固定 Python hash seed。

| 接受任务指标 | full-fit | pilot-fit |
|---|---:|---:|
| 类别熵 nats | 1.3313 | 0.8144 |
| 最少类比例 | 0.1067 | 0.0503 |
| 图节点数 | 12.4070 | 10.5741 |
| 活跃节点数 | 10.4568 | 8.7253 |
| 边数 | 69.6296 | 50.7747 |
| 有效特征数 | 48.6428 | 47.4113 |
| 实际类别数 | 5.3982 | 5.3968 |
| 类别特征占比 | 0.3956 | 0.4265 |
| Ridge 留出 MSE/常数 MSE | 0.5796 | 0.5545 |
| ExtraTrees 留出 MSE/常数 MSE | 0.4310 | 0.4514 |

这些不是浮点归约顺序导致的小变化。它们也不直接证明最终训练精度下降，但不足以支持“至少保留当前复杂度”。组件计数接近不能抵消实际任务难度/覆盖变化。详见 [旧质量审计](prior_fast_v2_evaluation_20261101.json)。

完整生成实验曾显示 pilot wall 33.5869→31.6482 s，但 742 次动作全部 defer，正式过滤次数 687→594。这一差异来自数据生成和重试分布变化，不能归因于筛选收益；p99 还从 1.132→1.771 s。

历史测试覆盖了当时实现，不作为当前测试计数。当前有效测试与新结果见新报告；已删除功能对应的测试也已删除。
